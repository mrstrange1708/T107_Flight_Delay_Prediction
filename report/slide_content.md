## Slide 3: The question, made measurable

**Headline:** A yes/no question asked at 05:00, using only what is known then

**On the slide (three big numbers):**
- 336,776 scheduled flights from JFK, LGA and EWR
- 327,346 labelled flights (8,255 cancelled + 1,175 diverted have no arrival delay)
- 0.245 of labelled flights arrive ≥ 15 minutes late

**Problem statement (one line):** Using the published schedule, static aircraft data and the delays of earlier days, predict at 05:00 on day D whether each departure will arrive 15+ minutes late, maximising PR AUC on future months, with flag lists at precision ≥ 0.5.

**Decisions:**

> **Decision 1: Binary classification: delayed = arrives ≥15 min late**  
> *Why:* Decision is yes/no; BTS definition; delay minutes skewed (skew 3.36). Regression on minutes rejected.  
> *What happened:* 327,346 labelled flights, 0.245 delayed.  
> *Verdict:* adopted
>
> **Decision 2: Predict at 05:00 on day D; post-departure columns banned; history ends on D-1**  
> *Why:* Early enough to act; about 3% of the previous day's flights land after midnight, so “end of previous day” is not exact.  
> *What happened:* Leakage tests pass (2 passed in 7.08s); no post-departure column is a feature.  
> *Verdict:* worked
>
> **Decision 3: Cancelled/diverted flights unlabelled but kept on the schedule**  
> *Why:* Label undefined; inventing one would fabricate data. They still occupy the schedule.  
> *What happened:* 8,255 cancelled + 1,175 diverted excluded from training and scoring, counted in congestion features.  
> *Verdict:* adopted

**Say:** "Three choices fix the problem before any model. Classification, because the decision is yes/no and the BTS uses 15 minutes. 05:00, because it is early enough to act, and because about 3% of the previous day's flights land after midnight, so 'end of the previous day' would not be exact. And we leave cancelled flights unlabelled, because inventing a label would be fabricating data."

**If asked:** *"Why not predict delay minutes?"* Delay minutes are heavily skewed (skewness 3.36, 99th percentile 204 min, maximum 1127 min). A regression model would chase rare multi-hour delays that do not change the yes/no decision.

## Slide 4: Success is defined before any model exists

**Headline:** Accuracy would reward a useless model, so we chose PR AUC first

**On the slide:**

- Metric set: PR AUC (main) · ROC AUC · Brier score · ECE (calibration) · lift = PR AUC / base rate · precision/recall at a threshold
- Random scoring gives PR AUC = base rate, so lift 1.0 means random.

**Decisions:**

> **Decision 4: Metric fixed before modelling: PR AUC (+ ROC AUC, Brier, ECE, lift)**  
> *Why:* Accuracy rewards “always on time”.  
> *What happened:* “Always on time” scores 0.863 accuracy in September with zero recall; random scores PR AUC ≈ base rate.  
> *Verdict:* worked
>
> **Decision 6: Confidence intervals by day-block bootstrap**  
> *Why:* Flights on one day are not independent.  
> *What happened:* Test CIs are about ±0.05 wide (LR [0.351, 0.459]), which is what makes the LR/boosting gap non-significant.

**Say:** "If we had used accuracy, the model that never predicts a delay would score 86%. PR AUC focuses on the delayed class. Our confidence intervals resample whole days, because flights on the same day share weather and are not independent."

**If asked:** *"What does lift 1.56 mean?"* Logistic regression's PR AUC is 1.56 times what random ranking would score on the same flights.

## Slide 7: Yesterday matters, last week does not

**Headline:** The autocorrelation of the daily delay rate chose our history windows

**On the slide:**
- ACF lag 1 = **0.343**, PACF lag 2 = **-0.109**, so the memory sits in yesterday
- ACF lag 7 = **0.008**, so there is no week-to-week memory; the weekly pattern is a fixed day-of-week effect
- ADF test rejects a unit root (p < 10⁻¹⁰): shocks fade, and the daily rate returns to its mean

**Visual:** `02_daily_acf_pacf.png`.

**Decisions:**

> **Decision 11: History windows chosen from ACF/PACF of the daily delay rate**  
> *Why:* ACF lag 1 = 0.343, PACF lag 2 = -0.109, ACF lag 7 = 0.008 ⇒ 1-day window + day-of-week features; 7/28-day windows only for small groups.  
> *What happened:* In notebook 03 the history group raised September PR AUC from 0.209 to 0.261.  
> *Verdict:* worked

**Say:** "We let the data choose the windows. A strong lag 1 with a PACF cut-off after lag 1 is an AR(1)-like pattern, so a 1-day window. Lag 7 is about zero, so we capture the weekly pattern with day-of-week features instead. We still use 7- and 28-day windows for small groups like one flight number, because a single day is too noisy for them."

## Slide 14: Gradient boosting, and the trap we found

**Headline:** Early-stopping on the month you report inflates boosting's score

**On the slide:**
- Boosting = gradient descent in function space: each tree fits r = y − p, with Newton leaf values Σr / Σp(1−p)
- Our from-scratch version: September log loss 0.4165, PR AUC 0.208. scikit-learn: identical.

| Month | Early-stop on the scored month | Honest: stop on m−1, refit, score m |
|---|---|---|
| Jul | 0.571 | 0.545 |
| Aug | 0.392 | 0.376 |
| Sep | 0.242 | 0.225 |
| Mean | 0.402 | 0.382 |

- **+0.020** of the optimistic mean came from the stopping rule seeing the answers

**Visual:** `05_scratch_boosting_loss.png` + a two-bar-per-month chart of the table.

**Decisions:**

> **Decision 26: Gradient boosting from scratch, checked against scikit-learn**  
> *Why:* Prove the theory (trees fitted to r = y - p, Newton leaf values).  
> *What happened:* September log loss 0.4165 and PR AUC 0.208, identical to scikit-learn.  
> *Verdict:* verified
>
> **Decision 27: Honest early stopping: stop on month m-1, refit, score m**  
> *Why:* Early-stopping on the scored month lets the stopping rule see the answers.  
> *What happened:* Same configuration: optimistic mean 0.402 vs honest 0.382 (+0.020 inflation avoided).  
> *Verdict:* trap found

**Say:** "This is the finding we are proudest of. If XGBoost early-stops on September and you then report September, the stopping rule has already seen the answers. For the same configuration that adds 0.020. Every boosting number after this slide uses the honest protocol."

> *Why:* Tuned boosting is the fair test of the project's model.  
> *What happened:* Best: lr 0.03, depth 3, min child weight 50, subsample 0.7, colsample 0.5, λ 1.0 → 0.386. All 8 lie in 0.376–0.386, below LR (0.409).  
> *Verdict:* boosting behind LR
>
> **Decision 29: Hybrid: XGBoost starts from LR's logit (base_margin) and learns corrections**  
> *Why:* Zero trees = plain LR, so it should never be much worse.  
> *What happened:* Rolling mean 0.406 (LR 0.409, boosting 0.386); trees per fold [16, 1219, 15].  
> *Verdict:* matches LR
>
> **Decision 30: Final tree count = median of the fold counts**  
> *Why:* One calm month would stop far too early.  
> *What happened:* Boosting folds [40, 110, 13] → 40 trees; hybrid → 16; September alone would pick 1.  
> *Verdict:* worked

**Say:** "Tuning moved boosting only a little, and every configuration stayed below logistic regression. Shallow trees won. The tree count chosen by early stopping swings between months, which tells us the non-linear structure does not transfer reliably. **If asked:** *"Gain vs permutation importance?"* Gain is loss reduction inside training and favours features with many split points. Permutation is the drop in held-out PR AUC when a feature is shuffled, which is what the model really relies on.

## Slide 20: Limitations we found ourselves

**Headline:** What we would flag before anyone else does

1. **Small selection optimism:** C = 0.001 was chosen on September and reused in the rolling comparison whose September fold is the same month (0.2655 vs 0.2624 with C = 1). Boosting's configuration was also picked on the folds it is reported on. The test set is unaffected.
2. **Small search:** 8 of 288 configurations; their spread was only 0.010, against a 0.023 gap to logistic regression.
3. **Unstable hybrid fold:** August stopped at 1219 trees, against 16 and 15; the median rule absorbs it.
4. **One month, one year:** the ablation uses October and a fixed tree count; one year cannot separate season from trend.
